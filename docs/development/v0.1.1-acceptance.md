# SignalRadar v0.1.1 验收记录

日期：2026-10-13。状态：候选版本，核心流程已验证，最终发布验收尚未完成。

## 检查与实施

检查了 Topic / Item / Digest ORM、SourceAdapter、采集/分析/简报服务、Scheduler、REST Router、前端与 Trace。保留已有两阶段 AI、10 条筛选、JSON 容错及 Trace；主要新增共用 TopicUpdateService、流式更新入口、Topic 级互斥和统一工作台。

基线后端运行结果为 168 passed、3 failed，失败均是本地 PostgreSQL 端口连接超时，不是 pytest 临时目录或业务断言。Windows 服务 postgresql-x64-18 为 Stopped；尝试启动被当前权限拒绝，用户明确选择先完成离线验收。之后完整离线测试保留 PostgreSQL 集成测试为 opt-in，不删除或降低覆盖率。

## Digest 失败证据及修复

既有真实 Trace 中 deepseek-r1:8b 两次响应均为 HTTP 200、done_reason=length、content 长度 0，eval_count=2048；thinking 长度分别约 4720 / 4571 字符。这表明输出预算耗尽在推理中，而不是网络失败或单纯 JSON 格式错误。

Digest 首次输出预算改为 4096，一次重试为 8192；每次超时 180 秒。temperature=0、stream=false 和 title/summary Schema 保留。空输出与超时提供独立友好错误，JSON 容错和最多一次重试继续复用。语义校验同时使用数据隔离、语言/Topic 关键词和明显任务漂移检查；正常引用的安全攻击样本不再仅因短语被拒绝。

## 产品改动

- 总览：最新简报为主，计数、最近发现、真实主题采集数量/时间、运行状态为辅。
- 我的主题：一键更新为主，独立操作放入高级入口，增加搜索与启用状态筛选；删除保留二次确认。
- Item：原始信息与 AI 区分，来源摘要可折叠，状态筛选，保留原文链接。
- Digest：独立阅读页、主题筛选和历史切换，纯文本安全展示，不伪造引用关系或章节结构。
- UI Tokens：暖浅灰、青绿色强调、系统中文字体、统一边框/按钮/表单/标签/Focus/错误。

## 已知限制与发布条件

- PostgreSQL 需启动后重跑 3 项集成测试，并完成真实生产库重启读取与 Alembic 验证。
- 浏览器桌面/窄屏和键盘操作仍需人工验收；当前不宣称最终 release-ready。
- 更新进度只随响应存在，刷新后不能恢复；当前推理可能仍在完成，先读取结果再重试。没有永久任务队列。
- Topic 锁仅保护同一个后端进程，不支持多 worker 或多个后端实例。
- 推理预算更大可能增加耗时；轻量检查不能保证事实正确或完全防止漂移。
- 全局来源 ID 去重使同一 Item 只归属一个 Topic，历史没有精确 Item 关联表；读取暂不分页。
- 真实 YouTube、Windows 通知及长时间连续运行未在本轮重新验收。
- 未新增信息源、登录、云部署、RAG、Embedding、事件聚类或大型基础设施。

API / 前端版本为 0.1.1。没有创建 Git tag，也没有发布 GitHub Release。
